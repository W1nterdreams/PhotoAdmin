# Настройка доступа PhotoAdmin

Основные параметры доступа находятся в `js/config.js`.

## Личный режим пользователей

```js
export const ALLOW_USERS = true;
```

- `true` — любой пользователь, который запускает Mini App напрямую, работает со своими личными фотоальбомами VK.
- `false` — прямой пользовательский запуск блокируется. Остаётся только работа из разрешённых сообществ.

Дополнительного списка пользователей нет: при включённом `ALLOW_USERS` личный режим доступен всем пользователям приложения.

## Разрешённые сообщества

```js
export const ALLOWED_GROUP_IDS = Object.freeze([
    173909287
]);
```

Чтобы подключить ещё одно сообщество, добавьте его числовой ID без знака минус:

```js
export const ALLOWED_GROUP_IDS = Object.freeze([
    173909287,
    123456789,
    987654321
]);
```

При запуске из сообщества приложение дополнительно проверяет роль, которую VK передаёт в launch params. Управление разрешено ролям `admin`, `editor`, `moder`. Участники `member` и пользователи без роли не получают режим управления сообществом.

## Как выбирается владелец альбомов

Приложение автоматически определяет источник запуска:

- запуск из сообщества: `owner_id = -group_id`;
- обычный запуск Mini App: `owner_id = user_id` текущего пользователя.

Все основные модули альбомов, фотографий, комментариев, поиска и локального индекса дальше используют единый `getOwnerId()`, поэтому данные разных пользователей и групп не смешиваются.

## Важно про уровень защиты

`ALLOW_USERS` и `ALLOWED_GROUP_IDS` находятся в клиентском JavaScript, поэтому это управление режимом работы приложения, а не серверная граница безопасности. Реальные права на изменение альбомов всё равно проверяет VK API по токену пользователя. Если в будущем белый список групп должен быть неизменяемым со стороны клиента, его проверку нужно перенести на backend с проверкой подписанных launch params.
